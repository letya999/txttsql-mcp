# Конфигурация

Скопируйте `config.example.toml` в локальный `config.toml`. Для каждого `[[sources]]` задайте уникальный `id`, `kind`, адрес, БД, пользователя, ссылку на пароль, allowlist и лимиты. `postgres` и `cockroach` используют TLS с проверкой имени сервера по умолчанию; `clickhouse` использует HTTPS. `allow_insecure=true` допускается лишь для изолированного тестового окружения.

`password`, `user_secret` (вместо статического `user`) и токены метаданных принимают `env`, `file` или `broker`. Broker запускается без shell, с пятисекундным таймаутом и ограниченным stdout. Его stdout должен содержать только один секрет с возможным переводом строки в конце. PostgreSQL/CockroachDB пулы обновляются через пять минут, ClickHouse и HTTP токены читаются при запросе. Права чтения и управление ротацией задаёт внешний secret store и администратор БД.

`[memory] enabled=false` отключает запись запросов и карточек метаданных. `ontology_path` можно направить на существующий каталог `txttsql/memory`; `find_context` ищет там определения и правила, а `explore_graph` читает связи из `graphs/*.json`, не изменяя файлы. Оба инструмента работают независимо от записи памяти. `[openmetadata]` и `[airflow]` задают опциональные HTTPS origin URL. Авторизация: `token` (Bearer) или пара `basic_user` + `basic_password` (Basic; пароль — ссылка на секрет). Airflow адаптер использует REST API v2 по умолчанию (Airflow 3); для Airflow 2 задайте `api_version = 1`. Поиск DAG просматривает до 1000 элементов и помечает неполный результат.
