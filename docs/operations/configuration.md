# Конфигурация

Внешние `[[plugin_databases]]` и `[[plugin_metadata]]` настраиваются по [контракту плагинов](plugins.md).

Скопируйте `config.example.toml` в локальный `config.toml`. Для каждого `[[sources]]` задайте уникальный `id`, `kind`, адрес, БД, пользователя, ссылку на пароль, allowlist и лимиты. `postgres` и `cockroach` используют TLS с проверкой имени сервера по умолчанию; `clickhouse` использует HTTPS. Для внутреннего удостоверяющего центра задайте `ca_file` с PEM-сертификатом: файл монтируется отдельно, проверка имени сервера остаётся включённой. То же поле доступно для OpenMetadata и Airflow. `allow_insecure=true` допускается лишь для изолированного тестового окружения и несовместимо с `ca_file`.

`password`, `user_secret` (вместо статического `user`) и токены метаданных принимают `env`, `file` или `broker`. Broker запускается без shell, с пятисекундным таймаутом и ограниченным stdout. Его stdout должен содержать только один секрет с возможным переводом строки в конце. PostgreSQL/CockroachDB пулы обновляются через пять минут, ClickHouse и HTTP токены читаются при запросе. Права чтения и управление ротацией задаёт внешний secret store и администратор БД.

`.env` загружается только по явному `--env-file PATH`: `txttsql-mcp --config PATH --env-file PATH`. Значения уже заданных переменных окружения имеют приоритет. Держите файл вне Git; сервер не ищет и не читает `.env` автоматически.

Windows Credential Manager подключается через `broker`: создайте Generic Credential и укажите абсолютный путь к `python.exe` как `program`, а в `args` — путь к `examples/windows_credential_broker.py` и имя credential target. Broker читает запись в текущем пользовательском сеансе. Для HTTP-хранилища есть `examples/http_secret_broker.py`: оно требует HTTPS, `TXTTSQL_BROKER_TOKEN`, при внутреннем CA — `TXTTSQL_BROKER_CA_FILE`; редиректы запрещены. Флаг `--allow-insecure-local` допускает HTTP только на loopback для теста. Оба broker возвращают секрет через stdout, поэтому храните свои входные учётные данные вне TOML.

Для БД за SSH используйте OpenSSH port forwarding с проверенным host key: `ssh -N -L 127.0.0.1:15432:db.internal:5432 user@bastion`. В `[[sources]]` задайте `host='127.0.0.1'` и `port=15432`. Встроенного SSH-туннеля нет; проверка TLS-имени БД остаётся включённой, поэтому имя в сертификате должно совпадать с `host` источника.

`[memory] enabled=false` отключает запись запросов и карточек метаданных. `ontology_path` можно направить на существующий каталог `txttsql/memory`; `find_context` ищет там определения и правила, а `explore_graph` читает связи из `graphs/*.json`, не изменяя файлы. Оба инструмента работают независимо от записи памяти. `[openmetadata]` и `[airflow]` задают опциональные HTTPS origin URL. Авторизация: `token` (Bearer) или пара `basic_user` + `basic_password` (Basic; пароль — ссылка на секрет). Airflow адаптер использует REST API v2 по умолчанию (Airflow 3); для Airflow 2 задайте `api_version = 1`. Поиск DAG просматривает до 1000 элементов и помечает неполный результат.
