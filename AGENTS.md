# txttsql-mcp

Перед изменениями читай [docs/architecture/overview.md](docs/architecture/overview.md), [docs/engineering/quality-gates.md](docs/engineering/quality-gates.md) и активную спецификацию в [specs/active/](specs/active/). Текущий ход работы — в [.work/in-progress/](.work/in-progress/).

## Правила

- Не читай и не коммить реальные секреты, `.env`, `config.toml` или runtime SQLite.
- Не выполняй запросы к рабочим базам при проверке кода. Интеграционные тесты используют только явно созданные тестовые сервисы.
- Каждый пользовательский SQL-запрос проходит `guard::validate` до выбора адаптера; внутренние запросы каталога собираются только из проверенных имён. Новый адаптер обязан сохранить read-only защиту на стороне движка.
- Не добавляй новые источники через прямой сетевой вызов из MCP handler. Добавляй адаптер в `database` или `metadata` и проверяй границы данных.
- Документация: `docs/` — текущее состояние, `specs/active/` — требования, `docs/adr/` — решения, `.work/` — процесс. Это разделение взято из `memory_bank_setup`.
- Проверка: `just ci`, затем локальный security scan. Перед коммитом `git diff --check` и проверка отсутствия секретов.

Публикация, push, деплой и подключение реальных учётных данных требуют отдельного решения владельца.
